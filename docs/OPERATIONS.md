# 콘텐츠 운영 안내

## 운영 원칙

앙두의 실제 기록, 확인한 정보, 작성 예시를 구분합니다. 매장명·주소·동반 조건·방문 후기는 확인 없이 만들지 않습니다. 초기 글은 구조를 확인하기 위한 예시 6편이며 상업적 추천·실제 경험을 뜻하지 않습니다.

## Markdown으로 글 추가

`src/content/posts/slow-walk.md` 등을 복사해 영문 소문자·숫자·하이픈 파일명으로 저장합니다. 폴더 하위에 넣지 않습니다. 파일명은 섹션 내 URL이 되므로 공개 후 가급적 유지합니다. 예: `my-walk.md` → `/stories/my-walk/`.

```md
---
title: "앙두와 함께한 오늘의 산책"
description: "실제 방문한 길과 그날의 장면을 간단히 소개합니다."
section: stories
category: 산책일기
date: "2026-10-23"
tags: [앙두, 산책]
image: andu-01
imageAlt: "잔디 옆 산책로에 서 있는 앙두"
sample: false
draft: true
---

## 기억하고 싶은 순간

확인한 실제 기록을 작성합니다.

## 다음에 챙길 것

- 실제 사용한 준비물
- 다시 확인할 사항
```

작성 중에는 `draft: true`, 검수 후 `draft: false`. draft는 목록·상세·검색·sitemap에서 모두 제외됩니다. future date로 예약 발행하지 않습니다. 날짜는 정렬/표시용이므로 미래 날짜도 draft가 false이면 즉시 공개됩니다.

| 컬럼 | 타입·허용값 | 기준 |
|---|---|---|
| title | 문자열, 필수 | 글 제목 |
| description | 문자열, 필수 | 카드·검색·검색엔진 설명 |
| section | stories / guides / places | URL 및 메뉴 분류 |
| category | 문자열, 필수 | 목록 필터 자동 생성 |
| date | `"YYYY-MM-DD"` 문자열 | 실제 게시일, 최신일 순 정렬 |
| tags | 문자열 배열 | 검색·태그 링크 |
| image | andu-01 / andu-02 / andu-03 | src/assets/*.png와 연결 |
| imageAlt | 문자열, 필수 | 사진의 실제 내용 |
| sample | boolean, 기본 true | 예시면 true, 상세 noindex |
| draft | boolean, 기본 false | 비공개 초안이면 반드시 true |
| location | 문자열, 선택 | 장소의 확인한 지역 |
| checkedAt | 문자열, 선택 | 예: `2026-10-23 · 공식 안내 확인` |

문자열 날짜와 `true/false` 타입을 지킵니다. 잘못된 section/image/date 형식이나 필수값 누락은 빌드를 실패시켜 게시를 막습니다. 파일명 중복과 잘못된 링크는 별도 검수합니다.

## 앙두 사진 및 BI

1. 실제 사진 3장은 `src/assets/andu-01.png`~`andu-03.png`로 반영되어 있습니다. 추가·교체 기준은 `src/assets/README.md`를 확인합니다.
2. 원본 사진 촬영 사실을 글의 경험과 연결할 때 실제 촬영 장소·날짜를 확인합니다. 원본만으로 확인되지 않는 사실은 적지 않습니다.
3. 각 Markdown의 imageAlt를 실제 장면과 일치시킵니다. 홈의 Photo alt도 수정합니다.
4. 로고 원본은 승인된 B안 `src/assets/andu-logo-approved-b.png`입니다. 빌드 시 `scripts/sync-brand.mjs`가 바깥 여백을 정리하고 비율을 유지해 PNG·WebP·파비콘을 생성합니다. SVG 경로는 호환용 이미지 래퍼이며 벡터 로고가 아닙니다.
5. 이후 디자인 변경은 반드시 시안 이미지를 먼저 보여주고 사용자 승인을 받은 뒤 사이트에 반영합니다. 승인된 그림의 형태·표정·색상을 임의로 다시 그리지 않습니다.
6. 목록·상세·홈을 모바일과 PC에서 확인합니다.

## 검색과 목록의 계산 기준

- draft 제외 후 date 내림차순, 같은 날짜는 파일 ID 순
- 검색 대상: 제목+설명+카테고리+태그+Markdown 본문. 공백으로 구분한 검색어는 모두 포함되는 문서를 찾음(AND)
- 한글·영문 유니코드 정규화 후 영문 대소문자 구분 없음
- 검색어는 최대 100자, 서버 저장·외부 전송 없음. 주소의 q에 남으므로 브라우저 기록에는 남음
- 내용은 textContent로 삽입하여 검색어/문서의 HTML 실행 방지
- 인덱스를 못 불러오면 오류 안내 후 재검색 가능
- 카테고리 필터는 목록 내 항목을 숨기고 보임. JavaScript 미사용 시 전체 목록·상세 이용 가능
- Instagram은 외부 링크, API 연동·자동 피드·인스타그램 사진 무단 복사 없음

## 담당 및 주기

| 담당 역할 | 할 일 | 산출물 |
|---|---|---|
| 운영자(초기 1인 가능) | 실제 기록·권리 확인·사진 선택 | Markdown·원본 PNG |
| 검수자(초기 운영자 겸임) | 사실·이용 조건·개인정보·오탈자 확인 | 검수된 글, 장소 확인일 |
| 게시 담당(초기 운영자 겸임) | 검사·GitHub 반영·배포 상태 확인 | 배포 URL·커밋 기록 |

게시할 때마다 검수합니다. 장소 조건은 방문 전 재확인이 필요함을 글에 명시하고, 수정 제보나 변경 확인 시 갱신합니다. 계정 비밀번호/API 키는 소스에 넣지 않습니다.

## 게시 순서 및 오류 대응

1. 초안 작성 → 실제 정보 검수 → draft 해제
2. `pnpm check && pnpm build && pnpm verify` (PowerShell 구버전에서는 한 줄씩 실행)
3. `pnpm release-check`로 예시·사진·주소 미완료 확인. 초도 상태에서 실패하는 것이 정상이며 수동 BI 확인도 필요
4. GitHub 반영 → Cloudflare 빌드 성공 확인 → 홈/검색/상세/모바일 확인
5. 빌드 실패: 최근 Markdown 헤더·타입 오류를 확인하고 수정. 배포 실패 시 이전 성공 버전 유지 여부 확인
6. 게시 후 오류: 해당 커밋 되돌리기 또는 Cloudflare 이전 배포로 롤백

사진은 빌드 시 WebP로 자동 최적화됩니다. 참조한 원본 PNG가 없으면 빌드가 실패합니다. 파일을 교체한 경우 Photo.astro의 표시 영역과 모바일·PC 크롭도 확인합니다.
